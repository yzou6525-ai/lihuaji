## 已接入的行为

- 后台按订单中的金额创建支付请求，浏览器不能指定实际收款金额。
- 微信生成订单专属 Native 二维码，支持普通商户与服务商两种参数结构；服务商模式必须使用获授权的服务商签名身份和特约商户号。
- 支付宝使用官方 SDK 生成电脑网站或手机网站收银台地址，返回原订单并向后台查询结果；跳转本身不是付款凭证。
- 支付通知必须通过签名、商户身份、订单、金额和渠道检查，重复通知只记账一次。
- 增加 `POST /api/orders/{id}/payment-status`，要求登录、订单本人及 CSRF 校验。生产环境限制查询频率。
- 付款弹窗每 10 秒核对一次，最多自动核对 12 次；离开页面或关闭弹窗立即停止，也可手动核对。
- 超时、金额不符或未知状态不记为支付成功，不释放已保留的库存。
- 支付配置本地检查通过后才记录所选渠道；网络超时后保留原渠道和商户单号，避免两种渠道重复付款。
- 取消未支付订单前先查单、再由渠道确认关闭；已经付款的订单转入售后。
- 退款重试始终使用同一个退款单号；校验退款交易号、订单和金额，查询支付宝退款时另外校验退款请求号。
- 支付宝收银台链接设置网关到期时间。仅在原链接带有可核实的到期记录、已过期且渠道签名确认交易不存在时，才允许释放订单；旧订单不作此假设。

| 文件 | 职责 |
| --- | --- |
| `backend/payment_sdks.py` | 开源 SDK 适配、密钥格式校验、固定微信验签公钥、响应时间戳检查、错误脱敏 |
| `backend/payments.py` | 下单、通知解析、主动查单、关单、退款业务规则 |
| `backend/app.py` | 原 prepay/notify/refund 路由及新增 payment-status 路由 |

| `web/payment.js` | 原付款弹窗的功能、有限轮询和到账核对 |
| `web/customer.js` | 原订单入口调用新支付模块 |
| `.env.example`、`compose.yml`、`deploy/production-check.py` | 部署配置、时区和商户配置预检 |
| `deploy/prepare-secrets.py`、`deploy/deploy.sh` | Linux 上按子目录准备只读密钥权限；拒绝链接，不把身份 JSON、密码和备份开放给 API 进程 |

现有数据库表继续使用 orders、payments、refunds、order_items、audit_logs。到期元数据使用订单已有的 options 字段，无需删除或重建数据库。

微信商户证书与匹配私钥已从官方工具导出，并与原申请请求核对一致。真实文件只存放在本机 `secrets/wechat/`；不放入代码包、GitHub、聊天或前端。

微信 APIv3 解密密钥已在官网设置成功，验签公钥及标识已取得并保存。一次真实商户签名的只读查询收到 ORDER_NOT_EXIST，未创建交易。仍需完成：关联正式 AppID、Native 权限和实际调用角色；支付宝应用及签约配置；可持续运行的 HTTPS 后台。配置保持未开放收款。GitHub Pages 中的静态展示页不能运行这套 Python 支付后台。

## 部署与验收顺序

1. 按原 `compose.yml` 部署后台、PostgreSQL、Redis、Nginx，使用独立的生产数据库和 HTTPS 地址。
2. 将获授权渠道的完整资料写入服务器私密环境文件，私钥只读挂载到 `/run/secrets/`。特约商户不能直接冒充服务商签名身份。
3. 完成原生产预检，再用 `PAYMENT_MODE=live` 启动；未配置的渠道仍会拒绝创建交易，不伪装成功。
4. 在真实收款账户中核对受控小额交易：创建、手机付款、异步通知、主动查单、后台到账记录、取消未付订单、申请和核实退款。
5. 真实交易验收完成后才向顾客开放。不能把演示支付标记成真实支付，也不能将个人收款码视作自动回调接口。

复测：先运行 `tests/test_platform.py`（其中包含初始演示数据数量断言），再运行 `tests/test_payment_sdks.py` 和其他现有测试文件。UI 验收服务器 `tests/payment_ui_server.py` 使用临时目录，不能用作生产服务器。

官方接入依据：普通商户 Native 准备 https://pay.wechatpay.cn/doc/v3/merchant/4015614538 ；特约商户与服务商 Native 授权 https://pay.wechatpay.cn/doc/v3/partner/4012076268 。特约商户的证书不等同于服务商 Native 支付授权。
